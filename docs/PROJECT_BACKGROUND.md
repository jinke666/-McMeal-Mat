# 项目背景：麦麦搭子 McMeal Mate

## 1. 项目概况
- 项目名称：麦麦搭子（McMeal Mate）
- 类型：AI 应用 / MCP 创新应用
- 参赛方向：2026 麦当劳 MCP 开发大赛（具体规则、截止时间和提交要求需以官方最新资料核验）
- 开发方式：两位开发者协作，使用 GitHub 管理代码，并使用 AI 编程工具辅助需求分析、设计、开发、测试和文档。
- 核心定位：面向真实消费场景的 AI 点餐搭配与消费优化助手。

## 2. 要解决的问题
用户在点餐时需要自己浏览菜单、计算价格、比较套餐和判断优惠。普通聊天机器人若没有真实数据和工具调用，也可能提供过时价格、虚构优惠或不支持的操作。

项目希望将 AI 的需求理解、推理和方案比较能力，与麦当劳官方 MCP 实际支持的业务能力结合，帮助用户完成从需求描述、数据获取、方案比较到下一步点餐决策的流程。

## 3. 目标场景
### 双人点餐
例如：“两个人吃，预算 60 元，一个喜欢鸡肉，一个不太能吃辣，希望尽量丰富。”
系统应在真实数据和可用能力范围内，生成合适组合并解释价格、搭配逻辑和取舍。

### 多人聚餐
例如：“四个人，预算 120 元，希望餐品多样。”
系统应综合人数、预算、餐品信息及用户偏好生成可比较方案。

### 优惠与消费优化
只有在官方 MCP 实际提供并成功获取相关优惠信息时，才能比较优惠方案；不得假设优惠券必然可用，或忽略适用条件。

### 个性化建议
可根据用户口味、忌口及实际可获得的营养数据提供建议。数据缺失时明确说明，不得编造营养数值或将一般建议包装为医疗结论。

### 从推荐到执行
只有在官方 MCP 确实支持、且满足必要确认条件时，才执行下单或相关操作。不得将模拟流程描述成真实订单已创建或已支付。

## 4. 产品原则
1. 真实数据优先：菜单、价格、优惠及营养信息尽量通过官方 MCP 或可核实的数据源获取。
2. 需求理解优先：先识别人数、预算、口味和约束，再生成方案。
3. 方案比较优先：提供可比较的完整组合，而不只是单品罗列。
4. 结果可解释：说明价格、优势、限制和推荐理由。
5. 用户保有决定权：重要操作前按实际接口要求取得确认。
6. 如实呈现不确定性：工具失败或数据缺失时明确说明。
7. 先做完整闭环：优先实现稳定的核心流程，避免盲目堆功能。

## 6. 竞争差异化方向
- 根据人数和预算做组合式推荐；
- 同时考虑预算、口味、品类多样性及真实可用的优惠；
- 用实际 MCP 调用驱动关键流程，而非只展示静态模拟数据；
- 解释方案的价格、优点、限制和取舍；
- 尽可能打通从自然语言需求到可验证结果的完整流程。

差异化必须通过真实用户场景和测试验证，不能仅依靠宣传文案。

## 7. 优先级建议
### P0
- 核验比赛规则与官方 MCP；
- 验证连接、工具清单和核心调用；
- 实现/验证自然语言需求解析；
- 实现/验证菜单数据获取；
- 实现/验证预算约束、价格计算和组合比较；
- 处理数据缺失、预算不足及工具失败；
- 完成可运行、可复现的核心演示。

### P1
- 在实际能力允许时加入优惠信息；
- 增加多人和口味约束；
- 在数据可靠时展示营养信息；
- 在官方能力允许时探索下单或点餐执行；
- 改善交互、异常提示和演示效果。

### P2
- 历史偏好记忆；
- 更多场景模板；
- 推荐反馈和分析。

实际优先级应根据现有代码、比赛要求、MCP 能力和剩余时间调整。

## 8. 交付标准
- 按文档可以启动和演示；
- 核心流程使用真实 MCP 数据，而不是全部依赖模拟数据；
- 价格计算和用户约束经过测试；
- 工具失败有清晰反馈；
- 不虚构优惠、订单或接口调用结果；
- 公开仓库无密钥和令牌；
- 按官方规则核验必需文件、声明、提交方式和截止时间；
- 演示者能说明问题、架构、创新点、验证结果与局限性。
